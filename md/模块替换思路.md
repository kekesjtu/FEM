- 1. 提前存储好高斯点信息
- 2. 查询高斯点信息

### ShapeFunction：形函数类，负责生成和存储测试函数和试探函数信息。它的主要业务有：
- 1. 生成形函数及其导数
- 2. 存储形函数信息
- 3. 查询形函数信息


### ProblemDef：问题类，负责描述有限元分析的问题。它的主要业务有：
- 1. 定义源项
- 2. 定义精确解（可选，如果有）
- 3. 定义精确解的导数（目前是手动输入，后续可以考虑用自动计算）
- 4. 施加边界条件

### Material：材料类，描述材料的物理属性。主要业务有：
- 1. 定义材料的属性，目前只是coefficient_c，为后续的多物理场耦合留下接口
- 2. 材料属性的查询

### ErrorAnalysis：误差分析类，负责对有限元解进行误差估计。它的主要业务有：
- 1. 计算多种范数误差
- 2. 输出误差结果

### Mesh：网格类，负责网格的生成、存储和导入。它的主要业务有：
- 1. 生成网格
- 2. 导入网格到对应数据结构中。包括坐标信息P、连接矩阵T、边界矩阵boundary_edges，全部节点数N、单元数M、每个单元的节点数等（与生成网格任选一种）
- 3. 存储网格
- 4. 查询网格信息

### FEMSolver：有限元求解器类，负责有限元分析的整体流程。它的主要业务有：
- 1. PreProcess：预处理，初始化计算配置、网格、材料、问题定义等
- 2. Assemble：组装全局刚度矩阵K和载荷向量b
- 3. ApplyBoundaryConditions：施加边界条件
- 4. SolveLinearSystem：调用线性求解器求解线性方程组，得到解向量u
- 5. PostProcess：后处理，计算误差，输出结果等

------------
上述部分的与原本主程序的解耦程度较低，建议在第二阶段进行替换实现
------------
另外，上述大部分程序在原本的程序中已经有面向过程的样例的实现，减少重新命名和较大的逻辑改动。

## 设计模式应用建议

### Factory Pattern 应用场景：（注意我用的版本是c++11，可能不能直接使用）
- **GaussPointFactory**：根据单元类型和积分阶数创建相应的高斯积分点对象
- **ShapeFunctionFactory**：根据单元类型创建对应的形函数对象
- **SolverFactory**：根据配置创建不同类型的线性求解器
- **MaterialFactory**：根据材料类型创建对应的材料对象

### Polymorphic Design 应用场景：
- **ShapeFunction基类体系**：支持线性、二次、三次等不同阶次的形函数
- **Material基类体系**：支持各向同性、各向异性、非线性材料
- **LinearSolver基类体系**：支持直接求解、迭代求解等不同求解策略
- **ErrorEstimator基类体系**：支持不同的误差估计方法
